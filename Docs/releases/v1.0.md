## Internal changes

Brought the repo up to the ecosystem standard established by the FitnessTracker /
GameKit / ParkedUp audit. No app behavior changed.

- Added `.githooks/pre-commit` + `scripts/install-hooks.sh` — enforces §9.6 Finder dupes,
  §9.13 no-print, §1/§9.4 DesignKit token discipline, and the §9.1 400-line cap (hard-block
  on new files, warn on modified). Only added lines are inspected. Verified by rejecting
  synthetic violations and replaying 39 files of real history with zero false positives.
- `core.hooksPath` set to the RELATIVE `.githooks`; an absolute path dies silently if the
  repo moves.
- Added CLAUDE.md §0.1 (dated status table) and §0.2 (where to look for live state).
  §0.1 records that the bundle ID is `lauterstar.HabitsTracker` with **no** `com.` prefix,
  unlike the siblings — that is the shipped value and must not be "fixed".
- Documented the hook as §9.19. Noted that HabitsTracker, as a DesignKit consumer, has no
  file that legitimately defines raw colors and therefore no file-level color exemption,
  unlike ClockKit and TripTracker which own local palettes.

## Fixes
- `Docs/RELEASE_PROCESS.md` Step 5 pointed at the dead `~/Desktop/HabitsTracker` path.
  Repointed to `~/Developer/`, added a push-confirmation check, and noted why a bare
  `~/Desktop/<Repo>` path must never go into a doc: a `cd` into a missing directory fails
  silently at the head of an `&&` chain and the whole step no-ops while looking successful.

## Risks / notes
- The Xcode scheme is autocreated rather than shared (no `.xcscheme` on disk). Builds work
  today, but sharing it would make it reliable on a fresh clone and in CI.
